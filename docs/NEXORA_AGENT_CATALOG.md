## Minimum acceptance gate for every role

1. Registry entry maps to a unique agent ID and department.
2. A task can be created, claimed, and moved through the allowed state transitions.
3. The configured provider returns non-empty output; provider failures become safe, actionable task errors.
4. The output satisfies the role's deliverable contract and includes evidence/assumptions.
5. Local memory write/read works; remote shared brain is tested only when configured.
6. Retry/recovery does not duplicate completed tasks or create an uncontrolled request storm.
7. Side-effecting actions remain approval-gated; drafts do not claim to have been published or sent.
